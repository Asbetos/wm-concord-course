Every number that decides H1 to H4 (a threshold, which models count, how a score is summarized) was written down and tagged in git before any zoo model was scored. This lesson reads that preregistration, its two amendments, the decision rules it fixes, and the few lines of code that hold everyone to it.

8.1Why write the rules down first

The hypotheses are judged against numbers a team could tune after seeing results without ever meaning to: move the agreement threshold a little, drop a model that looks odd, summarize a score per layer instead of at the best layer. Each choice is defensible on its own, and together they let the data say whatever looks best. The preregistration removes those choices: it fixes them while only training records exist, so the later analysis is confirmatory (testing what was planned) rather than exploratory (finding what looks interesting).

After a tag, the document can change only through a dated amendment at its end, written before the results it affects exist, and the paper reports every amendment.

8.3The decision rules

H1: do the four diagnostics agree?

For each of the six pairs of diagnostics, Kendall’s tau measures how consistently the two rank the admitted models in the same order. Spearman’s rho is reported next to it, and Kendall’s W summarizes all four diagnostics at once.

Amendment 1: agreement through competence

Every diagnostic is likely to score a better-trained model higher. Across a zoo whose legal move rate runs from about 0.56 to 0.97, the four diagnostics could agree only because they all follow competence. So each pair is also reported with competence (the validation legal move rate) controlled, as a partial Kendall tau:

τ(x, y | c) = ( τ(x, y) − τ(x, c) · τ(y, c) ) / √( (1 − τ(x, c)²) · (1 − τ(y, c)²) )

A pair whose raw tau agrees but whose partial tau disagrees is reported as agreement through competence, and the partial result decides whether two diagnostics measure the same thing. Because D1 is nearly the legal move rate itself, a pair that includes D1 is marked not interpretable when tau(D1, competence) is 0.90 or more (A5). A sensitivity run repeats H1 on the admitted models with a legal move rate of at least 0.90 (A3).

H2: is the disagreement systematic?

Per model, disagreement is the standard deviation of its four rank percentiles, one per diagnostic. It is regressed on architecture, scale and distribution. Disagreement is systematic if at least one factor is significant at 0.05 after Holm correction and its effect is larger than the noise floor: how much each diagnostic’s score varies across the three seeds of the same configuration. Otherwise it is reported as consistent with noise.

H3: which diagnostic predicts fragility?

The outcome is the fragility suite’s mean drop in legal move rate (Lesson 14). Amendment 1 divides it by the model’s own in-distribution legal move rate, so a strong model is not penalized for having more to lose, and it makes D1 the reference rather than a competitor, because D1 and fragility are both legal move rates. The contest is among D2, D3 and D4: each one’s partial Spearman correlation with relative fragility, controlling for D1, plus a regression with architecture and scale. A diagnostic is the best predictor if its partial correlation is the strongest in the expected negative direction and the bootstrap intervals of its differences to the other two exclude 0. A diagnostic adds to D1 if its own interval excludes 0. If none does, the finding is that nothing predicts fragility beyond the legal move rate.

H4: do the findings generalize?

H1 to H3 are computed on Othello and navigation and written down before any interpreter model is scored. Then the same code runs on the interpreter. The findings generalize if every pair keeps its H1 category and the H3 winner (or the absence of one) stays the same.

8.4How the code holds everyone to it

Each diagnostic script names the tag it needs and refuses zoo models until that tag exists in the local repository. The two anchors can be scored at any time, which is how the protocols were tried before they were frozen.

  • 590–592Ask git whether the tag exists locally. Nothing more: the check does not look at what the tag points to.
  • 612–615Any model id that is not an anchor is a zoo model. If the tag is missing, stop before a single model is loaded.

Two practical notes

The check runs in each script’s main(), so it guards the command line. Code that calls score() or interface.run() directly from Python is on its honour. And the check looks for the tag in your local clone: if a script refuses a zoo model on a machine where the tag should exist, run git fetch --tags.
