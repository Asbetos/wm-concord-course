train.py trains one zoo model: it loads the games, builds a transformer, an LSTM or a Mamba model at the chosen scale, trains it to predict the next move, measures two numbers on validation games, and saves everything. Every one of the 243 models goes through this one file.

About minutes · File: src/zoo/train.py

6.1Five steps

  1. Data. Load 1.28 million training games and 1,000 validation games of one distribution (Lesson 4) and turn the training games into tokens with to_tokens().
  2. Model. Build the architecture at the scale from SCALE_CONFIG (Lesson 5).
  3. Train. 5,000 optimizer steps of 256 games, predicting every next move.
  4. Evaluate. Next-token accuracy and legal move rate on the validation games.
  5. Save. The weights and a run summary under outputs/zoo/<model_id>/, and a training record in results/zoo_training/.
python src/zoo/train.py --arch transformer --scale small --distribution synthetic --seed 0   # one zoo model
python src/zoo/train.py --arch mamba --scale large --micro_batch 64                         # big model: batches in chunks of 64
python src/zoo/train.py --synthetic 200 --steps 20 --batch 16 --device cpu                  # smoke test: no data, no GPU

6.2Three architectures behind one shape

The diagnostics must never care which architecture they score. So every model class offers the same three methods: layer_outputs(x) returns the vector after each layer, readout(h) turns a last-layer vector into 61 next-move scores, and forward(x) is simply readout(layer_outputs(x)[-1]). That last line guarantees that the vectors D4 probes are exactly the vectors the model predicts from.

  • 77–78Each token gets a learned embedding plus a learned position embedding for positions 0 to 58: attention alone has no sense of order.
  • 79–83N standard PyTorch encoder layers: feed-forward width 4 × d_model, no dropout, GELU, and norm_first=True (pre-norm, as in GPT-2).
  • 90–96The causal mask lets position t attend only to positions 0 to t, so a prediction never sees the move it is predicting. The output after every block is collected.
  • 98–102readout applies a final LayerNorm and the linear head; forward is readout of the last block.
  • 105–108One nn.LSTM(num_layers=N) would compute the same thing but only return the last layer. A stack of single-layer LSTMs makes every layer reachable for D4. (Checkpoints of the earlier multi-layer version no longer load, which is why some LSTMs were retrained.)
  • 117–124No position embedding: the recurrence itself carries the order. The hidden state after each layer is collected.
  • 134–135The fast mamba_ssm CUDA kernels would not build on the course machines, so Mamba runs in plain PyTorch through mambapy. Same model, much slower (Lesson 5).
  • 141–142A selective state-space model: state size 16, a short convolution of 4, inner width 2 × d_model.
  • 146–153The model’s residual blocks are stepped through one by one, so the output after each block can be collected, exactly as mambapy’s own forward would compute it.

6.3The training loop

The task is next-token prediction, the same as a language model. The model reads a game and, at every position, predicts the move that comes next. In code that is one shift: the input is the game without its last token, the target is the game without its first.

  • 174–178The learning rate climbs linearly for 200 warm-up steps, then falls along a cosine to zero at step 5,000. It always uses the full budget as the end point, so a 300-step throughput run trains on the same schedule.
  • 184–185AdamW with weight decay 0.01, and cross-entropy that ignores target 0, the padding.
  • 190–191Micro-batching: Mamba large splits each batch of 256 into chunks of 64. Each chunk’s loss is divided by the number of chunks, and the gradients add up, so one optimizer step still sees all 256 games.
  • 198–199Each step draws 256 games at random, with replacement, from the loaded games.
  • 205–210The shift from the figure: read xc[:, :-1], score against xc[:, 1:], flattened over all positions.
  • 211–212Clip the gradient norm to 1.0, then step.
  • 200–215Wait for the GPU before and after each step, so the time per step is honest; that is what Lesson 5’s throughput numbers come from. The first 10 steps are dropped from the average (line 219).
  • 220–225The final loss is the mean of the last 20 steps.
A detail worth knowing

Because batches are drawn with replacement, a synthetic model draws about 63% of its 1.28 million games at least once, and about a quarter of them more than once. The comment in run_matrix.py (“so no game repeats within a run”) describes the intent of loading that many games, not exactly what sampling with replacement does. For the championship models, with only 110,005 games, every game is seen many times (Lesson 4).

6.4Evaluation: two numbers

  • 233–234Use the same chunk size as training, so big models fit, and build the validation games with legal moves (Lesson 3).
  • 238–243Next-token accuracy: how often the top prediction is the move the game actually played next.
  • 244Legal move rate: how often the top prediction is any legal move. This is D1’s number, computed here on validation games.

For the medium transformer trained on synthetic games with seed 0, next-token accuracy is 0.146 and the legal move rate 0.944. The gap is the point of the project: guessing the exact move is hard because random games pick among about 8.5 legal moves, while knowing which moves are legal is what a world model would give you. The legal move rate on these 1,000 validation games also decides whether the model is admitted to the study (Lesson 7).
