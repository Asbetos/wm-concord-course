4.2Two sources become three distributions

4.3Synthetic games: one byte per move

The othello_world corpus holds millions of games played by choosing uniformly among the legal moves, the same way the Random move button in Lesson 2 plays. Each .bin file is a flat run of bytes, 60 per game: byte k is the square (0 to 63) of move k. A game that ends early is padded with 255, which reads as −1 once the array is loaded as signed bytes.   • 183–195load_games(): read whole files as int8, reshape to 60 columns, stop once there are enough games, and keep exactly n_games. It warns, not fails, when the files run out.
  • 198–202load_split() joins the two and fails loudly if the folder is empty.

4.4Championship games: the WTHOR format

A WTHOR file starts with a 16-byte header, then one 68-byte record per game. The header’s bytes 4 to 7 hold the number of games; the rest (creation date, year, board size) is not needed. In each record, the first 8 bytes describe the game (tournament, the two players, the scores) and the last 60 are the moves, one byte each, written as 10 × row + column with both counted from 1. So 56 means row 5, column 6: F5. Here is the start of the first game in WTH_2025.wtb:

  • 216–220Read the file as unsigned bytes, take the game count from bytes 4–7 (little-endian int32), and check the file length agrees with it.
  • 221Keep bytes 8 to 67 of each record: the moves.
  • 222Convert 10 × row + column to the code’s square index, (row − 1) × 8 + (column − 1). A 0 byte (no move) becomes −1, the same padding as the synthetic files.
One orientation for every human game

The archive records every game in the same orientation: all 110,005 championship training games open with F5. Random games open with D3, C4, F5 and E6 about equally often. Lesson 14 shows how the fragility suite turns this into a test, by rotating and reflecting the board.

Worth knowing: what the models actually train on

Training asks for 1,280,000 games (Lesson 5), but the championship training split has only 110,005. So the championship models train on all 110,005 games, each seen about 11 to 12 times over the 5,000 steps. The mixed models ask for 640,000 of each, and the championship half is capped at 110,005: their training set is 750,005 games, about 85% synthetic. The training logs confirm it (mixed: 750005 train games). Validation and test sets of 1,000 games are a true 50 / 50, because 500 championship games always exist. The preregistration describes mixed as 50 / 50, so keep this in mind when you read results for the mixed models.

4.7The split rules every stage obeys

The preregistration fixes what each split may be used for. train is for training only. val is for checks during training and for anything a diagnostic fits: a probe, an adaptation, a choice of layer. test is for final scores only. A score measured on games that also helped choose a setting would look better than it is.

Every diagnostic scores a model on games of its own training distribution: a championship model is tested on championship games. Scoring on the other distributions is the fragility suite’s job.

4.8to_tokens(): the fast path for training

Training needs only the token sequence, not the boards. to_tokens() converts squares to tokens without calling replay(), which makes it fast enough for 1.28 million games. It does not check legality, which is safe because the synthetic games were generated legally and the championship games were already replayed during cleaning. Everything else in the project goes through build() (Lesson 3), which does replay and check.
