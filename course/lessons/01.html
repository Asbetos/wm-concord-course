About minutes · Sources: README.md, reports/proposal.md, reports/preregistration.md

1.1The question

Train a small model on Othello move lists, with no board and no rules, and it learns to propose legal moves. Has it built an internal picture of the board (a world model), or has it learned move statistics that happen to work?

Published papers answer with four different tests, and each paper picks its own. Nobody had run all four on the same models to see whether they agree. WM-Concord does exactly that: it trains a zoo of small models in worlds where the truth is known, runs all four tests on every model, and asks four questions.

  • H1Agreement. Do the four tests rank the models in the same order?
  • H2Disagreement. Where they disagree, is it systematic (tied to architecture, scale or training data) or noise?
  • H3Prediction. Which test best predicts a model breaking on shifted positions, measured by the fragility suite?
  • H4Generalization. Do the answers hold on a domain kept out of all earlier analysis (the interpreter)?
Why any outcome counts

If the tests agree, the cheap ones can stand in for the expensive ones. If they disagree, a paper that rests on one test is on weaker ground than it looks. The study reports either result.

1.2Why Othello: every move has an answer key

In Othello a move list fixes the board completely. For any position in any game, the rules can say what the board is and which moves are legal, so every test has an exact answer key to check the model against. New to the game? Lesson 2 teaches it in ten minutes.

The model’s input is tokens. The 60 squares a move can land on are tokens 1 to 60 (the four centre squares start occupied and are never played), and 0 is padding. The opening D3, C3, C4 reaches the model as 20 19 27.

All of this lives in one file, src/domains/othello.py. The trainer, all four tests, the fragility suite and the test suite import it, and no other file keeps its own copy of the rules. Lesson 3 opens it up.

Othello is the first of three planned domains. Navigation (street maps) and a small program interpreter come after 20 October; the interpreter is held out for H4.

1.3Four ways to test one model

The four tests look at different parts of the same model. Two only watch its output, one fine-tunes a copy of it, and one reads its insides.

Test Question it asks Score it writes Anchor scoressynthetic · championship Code · owner
D1Next-token validity Is the model’s top predicted move legal? Share of positions where the top move is legal 0.9996 · 0.8962 d1/next_token.pyViharika
D2State equivalence Same board reached two ways: same moves accepted? Different boards: told apart? 1 − mean of compression error and distinction error 0.9994 · 0.7663 d2/state_equiv.pyVenkatesh
D3Inductive bias Does pretraining help it learn “is square X mine?” from 64 examples? Balanced-accuracy gain over a random-weights twin 0.1397 · 0.0593 d3/inductive_bias.pyNikhil
D4Representation probing Can a linear probe read mine / theirs / empty from the activations? Probe accuracy minus control-task accuracy (selectivity) at the best layer 0.4345 · 0.2720 d4/representation_probe.pySiddu

Every test writes one number called score, and higher always means more world-model-like. D2’s natural numbers are errors, so it stores 1 minus the error. The four scores sit on different scales, as the anchor column shows. That is fine: H1 compares rankings with Kendall’s tau, so only the order of the models matters.

The anchors are the two published Othello-GPT models (Li et al. 2023), one trained on random games and one on championship games. Every test scores them as reference points, but they never enter the H1–H4 statistics, because they were trained with different code and a much longer budget.

1.4The pipeline: which script runs at each stage

The work runs as a chain of stages. Each stage is a script that reads files an earlier stage wrote, so any stage can be stopped, restarted or rerun on its own. One line matters more than the rest: no zoo model may be scored until the analysis rules are written down and tagged in git.

Where things stood on 19 October. The data was fetched on every training machine. 80 of the 81 Othello models had a training record, and the last one, a large Mamba in slice 4, was finishing. All the preregistration tags and fragility-v1 existed. D1–D4 had scored the two Othello-GPT anchors but no zoo model yet. Fragility, the master table and the H1–H4 analysis had not run.

Commands for each stage run from the repo root 
# Environment: conda activate wmconcord, or any venv built from requirements.txt
# (pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cu130)
# Training and scoring are GPU jobs. Check nvidia-smi first: one job per GPU.

# 1 · Get the data (once per machine; skips files already there)
bash src/shellscripts/fetch_othello_data.sh

# 2 · Plan the runs (frozen; rerun only to regenerate the two CSVs)
python src/component/run_matrix.py

# 3 · Train one model, or a whole slice
python src/zoo/train.py --arch transformer --scale small --distribution synthetic --seed 0
bash src/shellscripts/train_slice.sh 4 --dry_run     # print the plan only
bash src/shellscripts/train_slice.sh 4               # train; models that have a record are skipped

# 4 · Rebuild the registry (admitted = validation legal move rate of at least 0.50)
# This rewrites src/docs/zoo_registry.csv. Per train_slice.sh, commit only your
# training records, never this file.
python src/zoo/registry.py

# Plumbing check: loads models through the interface, prints legal move rates, saves nothing
python src/diagnostics/interface_check.py

# 5 · Score. Anchors: othello_gpt_synthetic othello_gpt_championship
#     --save writes results/D*/<id>.json
python src/diagnostics/d1/next_token.py           --models <id> ... --save
python src/diagnostics/d2/state_equiv.py          --models <id> ... --save
python src/diagnostics/d3/inductive_bias.py       --models <id> ... --save
python src/diagnostics/d4/representation_probe.py --models <id> ... --save

# 6 · Fragility suite (writes results/fragility/<id>.json)
python src/fragility/othello.py --model outputs/zoo/<id>/model.pt \
--arch <arch> --scale <scale> --train_distribution <dist> --seed <seed>

# 7 · Master table (writes results/master_table.csv and lists missing runs)
python src/component/results.py --domain othello

# 8 · Analysis H1–H4: not in the repo yet

# Any time: the demo and the tests
streamlit run demo/app.py
python -m pytest src/tests -q

# One-off checks from weeks 5 and 6
bash src/shellscripts/throughput.sh                  # cost per model, see src/docs/throughput.md
python src/diagnostics/d4/reproduce_nanda_probe.py   # reproduction gate against Nanda et al. 2023

One habit to know before reading any code

src/ is not a Python package. Files load each other by file path through a small _load() helper built on importlib, which you will see at the top of almost every file. That is why every command runs from the repo root.
