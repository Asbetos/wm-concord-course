Four diagnostics, five kinds of model, 972 result files. Two small modules keep that from turning into 20 special cases: interface.py makes every model look the same to a diagnostic, and results.py makes every result look the same to the analysis.

9.1One interface for every model

The anchors are TransformerLens models; the zoo is three PyTorch classes from train.py. A diagnostic should not care. ZooModel wraps any of them behind the same few calls, and two small subclasses translate those calls for each kind of model.

  • 104–107logits: tokens in, next-move scores out, under no_grad. Tokens can be a NumPy array or a tensor; _to moves them to the model’s device as integers.
  • 109–114activations: the vector after every layer, stacked into one tensor. The assert catches an adapter that returns the wrong number of layers or the wrong width.
  • 116–126logits_edited: run the model, but at chosen layers replace the vector at one position per game with whatever a function returns, in layer order, so later layers see the edit. This is what the D4 causal check needs (Lesson 13).
  • 128–134logits_patched: the simplest edit, replacing one layer’s vectors with given ones.
  • 136–139Calling the model is the same as logits, so a ZooModel works anywhere a plain model(tokens) is expected, such as othello.legal_rate().
  • 184–190For zoo models both calls are one line, because every train.py class already has forward and layer_outputs (Lesson 6).
  • 196–209Edits use PyTorch forward hooks on the layer modules: each hook replaces the layer’s output before the next layer reads it. The LSTM returns a tuple, so only its first element (the output sequence) is edited. The hooks are always removed, even if the forward pass fails.

9.3The diagnostic contract and run()

A diagnostic is any module that defines DIAGNOSTIC (“D1” to “D4”), a one-line METHOD, and one function:

def score(model, split, n_games, data_seed, **config) -> Result:
    games = oth.load_distribution(<the model's own distribution>, split, n_games, seed=data_seed)
    ...                                        # compute the diagnostic
    return itf.result_for(model, DIAGNOSTIC, method=METHOD, split=split, n_games=n_games,
                          data_seed=data_seed, score=<higher is better>, details={...})

Four rules come with it: score is the master-table number and higher always means more world-model-like; final scores use the test split and anything fitted uses val; games, boards and legal moves come from othello.py, never a copy; and errors are not caught to hide them.

  • 270–271Refuse a module that does not follow the contract, before any model runs.
  • 276–279Score the model, and check the result really is for this model and this diagnostic.
  • 280–286If anything goes wrong, record a failed result whose reason is the error, with a short traceback, and carry on. One broken checkpoint cannot stop a sweep of 81 models, and the failure is written down instead of silently missing.
  • 287–288Save every result, failed or not, unless save=False.

9.4One result format

Every diagnostic writes one JSON file per model, in one format, so the master table is a single join. The format was fixed before any diagnostic was written; changing it later would have meant changing all four.

make_result() fills the model fields from models.csv (an anchor passes them itself), sets run_id, stamps the provenance and validates. validate() refuses, before anything is written, a result with an unknown diagnostic or split, an ok status without a finite score, a failed or skipped status without a reason, an interval whose low end is above its high end, an empty model field, a wrong run_id, or details that are not plain JSON. Provenance

Every result records the git commit, the time, the Python, PyTorch and NumPy versions, the GPU (or cpu), the machine and the runtime. Any number in the master table can be traced back to the code and the machine that produced it, and a result computed from uncommitted code is easy to spot.

9.5Checking the plumbing

python src/diagnostics/interface_check.py
python src/diagnostics/interface_check.py --zoo othello_transformer_large_synthetic_s0 othello_lstm_small_synthetic_s0

This loads the synthetic Othello-GPT and the zoo models named, checks the shapes of logits and activations, and prints each model’s legal move rate on 1,000 test games of its own distribution. Nothing is saved. Expect about 0.999 for Othello-GPT and about 0.97 for the large transformer; anything far off means the plumbing, not the model, needs a look.
