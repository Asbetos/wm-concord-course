One model is one call to train.py. The Othello zoo is 81 of them, about 37 GPU hours, spread over four machines. This lesson covers the slice plan, the loop that trains a slice and survives restarts, the training record each model leaves behind, and the registry that turns those records into the list of models the study may use.

About minutes · Files: src/docs/zoo_slices.csv, src/shellscripts/train_slice.sh, src/zoo/registry.py, src/docs/zoo_registry.csv

7.1Four machines, four slices

Each team member has one g5.2xlarge instance with one A10G GPU. zoo_slices.csv assigns every Othello model to a slice, with its estimated minutes from the throughput table (Lesson 5), and the slices are balanced so that each machine finishes in about nine hours. The nine Mamba large models, about 2.4 hours each, are spread so that no machine gets more than three. Slice 0 holds the first four models, trained before the split to check the pipeline end to end.

Each row of the CSV also carries the model’s micro_batch: 64 for Mamba large, 0 (no chunking) for everything else.

7.2train_slice.sh: a loop that survives restarts

A slice runs for hours, usually inside tmux so it outlives the SSH session. The script trains one model after another and is built so that the answer to any crash is “run the same command again”.

bash src/shellscripts/train_slice.sh 4 --dry_run   # print the plan: one line per model with its command
bash src/shellscripts/train_slice.sh 4             # train it; models with a record are skipped
  • 50–51Read zoo_slices.csv row by row and keep only this slice’s rows (the header row is skipped too).
  • 53–58If the model already has a training record, skip it. This one check makes the whole loop restartable: finished models are never trained twice.
  • 59–60The train.py command, always at the frozen budget: 5,000 steps, batch 256, the slice’s micro-batch.
  • 66–67Each model’s output goes to its own log, outputs/zoo_logs/<id>.log. Success needs both a clean exit and the record file on disk.
  • 68–70Pull the legal move rate out of the log for the progress line.
  • 71–75A failure is reported with the last five log lines, and the loop moves on to the next model rather than stopping the slice.

At the end the script prints a summary, exits with an error if any model failed, and reminds the trainer to commit only the new records. Before the loop it also warns when src/ has uncommitted changes, because every zoo model should be trained from the same clean code.

Because every member trains a different slice and commits only their own records, four people never edit the same file, and pull requests never conflict.

7.4registry.py: from records to the zoo

The registry turns the records into one table, src/docs/zoo_registry.csv, and applies the admission rule: a model enters the H1–H3 analysis only if its legal move rate on the 1,000 validation games is at least 0.50. The rule was fixed in the preregistration from training records alone, before any diagnostic score existed. Why 0.50: an untrained model scores about 0.15, because roughly 9 of the 60 squares are legal at a typical position, and the first trained models scored 0.57 to 0.97. A model below 0.50 has not learned the task, so a world-model test would have nothing to measure in it.

  • 48–51The admission rule. With no threshold set the answer is tbd, which is how the column read before the preregistration fixed 0.50.
  • 54–69One record becomes one registry row: the model fields, the final loss, the validation legal move rate and next-token accuracy, training minutes, where it ran, the checkpoint hash and admitted.
  • 83–89Every record must belong to a model in models.csv, or the build stops: the zoo is exactly the run matrix, never more.
  • 90Rows come out in models.csv order, so the table never reshuffles as records arrive.
  • 109–111No record, no model: a checkpoint that was never recorded cannot be loaded through the registry.
  • 113–116A record whose checkpoint is not on this machine fails with a message naming the machine it was trained on: copy it from there, or from the team’s S3 bucket.
  • 117–120The SHA-256 of the file must match the record. A checkpoint that was retrained, copied wrongly or swapped is refused instead of being silently scored.
python src/zoo/registry.py                    # rebuild src/docs/zoo_registry.csv and print each architecture and scale's range
python src/zoo/registry.py --import_outputs   # first write records for older full-budget runs that have none

And the seed and the training distribution move a model much less than its architecture and scale do.

That spread is what the study wants: rank correlations between diagnostics only mean something when the models really differ. It also sets up the preregistration’s worry in Lesson 8: if all four diagnostics simply follow this legal move rate, they could agree without measuring the same thing.
